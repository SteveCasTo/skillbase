# Auditoría y corrección de feedback Sileo

## Alcance y entorno

- Rama `fix/sileo-visible-feedback`, creada desde `origin/development` después de fetch (`f388327`). Worktree separado en el directorio temporal aprobado.
- Navegador Chromium real mediante **playwright-cli**, aplicación aislada `127.0.0.1:4331`, API local existente y DB local existente. `PUBLIC_SITE_URL` se ajustó solamente en el proceso aislado para respetar Origin/CSRF; no se modificó OAuth ni la configuración Supabase.
- No se detuvo la aplicación original 4321; no hubo reset, seed, migraciones, reinicio Supabase, operaciones cloud ni cambios de permisos/reglas/PDF.
- No se añadieron pruebas ni suites. Se ajustaron únicamente dos expectativas existentes que dejaron de representar el diseño aprobado: error de Auth como toast visible y colores semánticos de feedback.
- **Este informe NO acredita todas las mutaciones de todos los módulos.** Distingue acciones observadas de lectura/montaje e inventario de código. Los pendientes al final son explícitos.

## Causas encontradas y correcciones

| Causa                                                                                    | Antes                                                                                                                                                                                 | Corrección                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auth descarta el aviso loading al fallar y coloca el fallo general en `data-auth-result` | POST real de credenciales inválidas: 422, cero toast de error, párrafo que aumenta el formulario                                                                                      | Fallos generales actualizan el mismo ID a error Sileo. Campos accionables siguen inline; no se repite el mensaje general dentro del formulario. El nodo vacío queda oculto incluso durante pending.                                                                  |
| Éxito inmediatamente seguido por `window.location.assign`                                | El documento y el store de notificaciones desaparecen antes de poder leer el resultado                                                                                                | Flash de presentación con destino y TTL de 30 s, consumido una sola vez al montar el host siguiente. Solo guarda título/destino/expiración, nunca valores de formulario ni credenciales. Storage bloqueado no interrumpe Auth.                                       |
| Estilos de feedback estaban acotados a `.private-shell`                                  | Auth/público no tenían las mismas garantías de superficie/texto. En la inspección dark se confirmó descripción negra sobre `card` oscuro por la especificidad del selector del vendor | CSS compartido de notificaciones y selector de descripción que gana a ambas variantes del vendor; misma superficie `card` y texto `card-foreground` en todos los hosts.                                                                                              |
| Colores privados confundían éxito con primary y warning con accent decorativo            | Éxito naranja, warning sin semántica consistente con el tipo                                                                                                                          | Tokens propios `feedback-success`, `feedback-warning`, `feedback-info` con variantes light/dark; error conserva destructive y loading muted-foreground. Texto e icono mantienen información sin depender solo del color.                                             |
| Pill de título mide una sola línea y descripciones se colapsan automáticamente           | Mensajes largos pueden exceder el ancho móvil o desaparecer del cuerpo demasiado pronto                                                                                               | Mensajes mayores a 40 caracteres sin descripción pasan íntegros al cuerpo, con título de estado breve. Ancho máximo responsive, descripción expandida durante el tiempo de lectura predeterminado de 8 s. Las duraciones explícitas de los productores se conservan. |
| Modal HTML nativo pertenece al top layer                                                 | Ningún z-index de un toast en body supera `dialog.showModal()`; los hermanos del modal son inert                                                                                      | El único host se porta al modal nativo activo y vuelve al documento al cerrarlo. Los diálogos React reciben el viewport por encima de sus overlays ordinarios.                                                                                                       |
| Botón toast de Sileo 0.1.5 no tiene activación de teclado                                | Swipe funciona, pero Enter/Escape sobre el aviso no lo descarta                                                                                                                       | Enter, Espacio o Escape sobre un toast enfocado descartan los avisos actuales. No se intercepta Escape de diálogos ni acciones internas del toast.                                                                                                                   |

No se atribuye el problema a una ausencia universal de host ni a hidratación fallida sin evidencia: BaseLayout ya montaba el host privado/Auth; `PublicInterestSection` ya montaba su host local. El montaje posterior a hidratación y los UUID existentes se preservaron. Las páginas públicas sin operaciones transitorias omiten el host deliberadamente.

### Tipos, temas y accesibilidad

- **Success:** operaciones reales de formatos, login y logout, light/dark desktop; mismo host durante navegación ClientRouter.
- **Error:** rechazo real de login, light desktop y dark mobile; descripción completa y sin duplicado general.
- **Loading:** acción de grupo retenida en navegador, visible sobre modal nativo dark; no se falsificó un resultado de servidor.
- **Warning:** export usa warning para límite/recuperación. Código y tokens inventariados; no se construyeron más de 1000 registros ni se provocó este resultado. Visual/acción reales **PENDIENTES**.
- **Info/action:** fachada/token disponibles, sin productor `info` encontrado en `src` durante el inventario. Visuales reales **PENDIENTES**; no se fabricaron acciones solo para mostrarlos.
- Escape sobre aviso comprobado en móvil/reduced-motion. El host mantiene el live region del vendor y no secuestra foco. No se realizó auditoría completa con lector de pantalla ni revisión matemática de todos los contrastes/iconos.
- No se optimizó la carga diferida del bundle de notificaciones de detalle: prioridad funcional es no perder avisos previos a hidratación. La observación de rendimiento queda separada del PR de assets/landing.
